## 📌 Project Overview

**Smart Compiler Error Detective** is an educational, interactive compiler analysis tool designed specifically for Computer Science & Engineering students studying **Compiler Design (CS / IT)**. 

Unlike traditional command-line compilers (`gcc`, `javac`, `clang`) whose cryptic messages often confuse learners, this detective demystifies compiler diagnostics by:
1. **Explicitly Categorizing Errors into Compiler Phases**:
   - 🔤 **Lexical Analysis (Scanner)**: Unrecognized characters, ill-formed numeric constants, unclosed literals, illegal tokens.
   - 🧱 **Syntax Analysis (Parser)**: Grammar violations, missing semicolons, unmatched parentheses/brackets, malformed control structures.
   - 🧠 **Semantic Analysis (Type & Scope Checker)**: Undeclared identifiers (with typo suggestions!), variable redeclarations, type assignment incompatibilities, static division by zero, missing or illegal return statements.
2. **Pinpointing Error Locations**: Highlights line number and column with gutter indicators and clickable line-jumping.
3. **Explaining in Simple English**: Translates formal compiler errors into clear, educational explanations of *why* the compiler rejected the construct.
4. **Providing Actionable Suggestions & 1-Click Fixes**: Recommends the exact correction and allows users to apply the patch directly into the editor with a single click.
5. **Interactive Academic Inspection**:
   - **Lexer Token Stream Table**: Inspect the exact token sequence (`Token ID`, `Type`, `Lexeme`, `Line`, `Column`) generated by Phase 1.
   - **Symbol Table & Scopes**: Inspect the symbol table (`Identifier`, `Type`, `Scope`, `Line Declared`, `Initialized`, `Usages`) populated during Phase 3.
   - **Session Error History**: Track changes across consecutive runs to measure error resolution progress.

## 🏗️ System Architecture

The project adopts a **modular compiler architecture**: each programming language has its own dedicated Analyzer containing a Lexer, Parser, and Semantic Analyzer, while all modules output to a unified, standardized Error and Token schema.

```
                    ┌────────────────────────┐
                    │      Source Code       │
                    └───────────┬────────────┘
                                │
                                ▼
         ┌─────────────────────────────────────────────────┐
         │     Language Factory: get_analyzer(lang)        │
         └───────┬────────────┬─────────────┬────────────┬─┘
                 │            │             │            │
                 ▼            ▼             ▼            ▼
             [ C Lang ]   [ C++ Lang ]   [ Java ]   [ Python ]
                 │            │             │            │
 ┌───────────────┴────────────┴─────────────┴────────────┴───────────────┐
 │                       COMPILER PHASES                                 │
 │                                                                       │
 │  1. Lexical Analysis (Scanner) ──► Tokens Stream + Lexical Errors     │
 │  2. Syntax Analysis (Parser)   ──► CST/AST + Syntax Errors            │
 │  3. Semantic Analysis (Scopes) ──► Symbol Table + Semantic Errors     │
 └───────────────────────────────┬───────────────────────────────────────┘
                                 │
                                 ▼
         ┌─────────────────────────────────────────────────┐
         │       Unified AnalysisResult Data Model         │
         │  (Errors, Warnings, Tokens, Symbols, Summary)   │
         └───────────────────────┬─────────────────────────┘
                                 │
                                 ▼
         ┌─────────────────────────────────────────────────┐
         │         Flask REST API Server (app.py)          │
         │    POST /api/analyze  •  GET /api/history       │
         └───────────────────────┬─────────────────────────┘
                                 │
                                 ▼
         ┌─────────────────────────────────────────────────┐
         │       Modern Single-Page UI (HTML/CSS/JS)       │
         │  • Code Editor with Line Gutter & Markers       │
         │  • Error Detective with Simple English Cards    │
         │  • 1-Click "Apply Fix" Automated Patching       │
         │  • Token Stream & Symbol Table Inspectors       │
         │  • Session History Slide-Over Drawer            │
         └─────────────────────────────────────────────────┘
```

## 🌟 Key Features

| Feature | Description |
| :--- | :--- |
| **Multi-Language Support** | C (C11), C++ (C++17), Java (JLS 17), and Python 3. |
| **Phase-Segregated Errors** | Errors are distinctly tagged with color-coded badges: Lexical (Amber), Syntax (Orange), Semantic (Red). |
| **Simple English Explanations** | Explains the underlying grammar or type rule violated in intuitive, student-friendly terms. |
| **1-Click "Apply Fix"** | Directly applies the suggested replacement snippet into the active editor buffer and automatically re-detects errors. |
| **Click-to-Jump Navigation** | Clicking any error card highlights and scrolls the editor directly to the offending line and column. |
| **Token Stream Inspector** | Displays the full token list produced by the Lexical Scanner with instant search filtering. |
| **Symbol Table Inspector** | Displays identifier names, data types, scope environments, declaration lines, and initialized states. |
| **Session Error History** | Tracks previous runs during the current session to visualize error reduction. |
| **Pre-Loaded Curated Samples** | Includes pre-loaded Buggy Demos, Clean Code, and targeted Phase Demos for each language. |
| **Dark & Light Mode** | Modern, eye-friendly theme toggle with persisted user preference. |

## 🚀 Getting Started

### Prerequisites
- **Python 3.10+** (Tested on Python 3.10, 3.11, 3.12, 3.13, 3.14)
- Web browser (Chrome, Edge, Firefox, Safari)

### 1. Installation
Clone or navigate to the project directory:
```bash
cd smart-compiler-error-detective
```

Install dependencies:
```bash
pip install -r requirements.txt
```

### 2. Launch the Application
Run the launcher:
```bash
python run.py
```
*(On Windows, you can simply double-click `run.bat`)*

The server will initialize and automatically open your default browser at:
```
http://localhost:5000
```

## 🎓 Academic Demonstration Guide (Viva / Presentation)

When presenting this project for a **Compiler Design** lab or course viva, demonstrate the following flows:

1. **Phase 1: Lexical Analysis Demo**
   - Select **C** and choose `🔤 Lexical Errors Demo` from the sample dropdown.
   - Show how the detective catches stray symbols (`$`, `@`), unclosed strings (`"hello;`), and malformed numeric literals (`123xyz`).
   - Switch to the **Tokens Stream** tab to show the scanner outputting token types (`KEYWORD`, `IDENTIFIER`, `OPERATOR`, `STRING_LITERAL`).

2. **Phase 2: Syntax Analysis Demo**
   - Select **C++** and choose `🧱 Syntax Errors Demo`.
   - Show missing semicolons, malformed `for` loops with incorrect semicolons, missing class terminating semicolon `class Student { ... };`, and wrong stream operators (`cout >>`).

3. **Phase 3: Semantic Analysis Demo**
   - Select **Java** and choose `🧠 Semantic Errors Demo`.
   - Show type incompatibility (`boolean isActive = 1;`), undeclared identifiers (`factor * unknownFactor`), and static division by zero (`50 / 0`).
   - Switch to the **Symbol Table** tab to show the symbol table with types, scopes, and declaration lines.

4. **Phase 4: Error Correction & Progress Demo**
   - Click **⚡ Apply Fix** on an error card.
   - Watch the editor automatically update the erroneous code line.
   - Show how the detective automatically re-analyzes and reduces the error count.
   - Open the **Session History** drawer to show the history of runs (e.g. 5 errors ➔ 0 errors).
